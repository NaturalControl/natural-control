\section{Problem Statement}
Visually impaired individuals can face many difficulties when navigating screen-based websites and
applications that rely on visual feedback. These barriers become especially 
challenging when completing complex, multi-step digital tasks that require the interpretation of changing
system states. This project aims to support independent task completion while allowing users to 
remain informed of relevant system changes and maintain control when completing digital work.

\subsection{Problem}
Visually impaired individuals may encounter significant barriers when 
completing computer tasks, as many websites and applications require visual interactions
to communicate information, present possible actions, and indicate changes in a system's state.
Complex and unfamiliar tasks can require users to navigate multiple applications, interpret changing 
interface and application states, recover from errors and unexpected outcomes, and determine if actions
were completed successfully. Managing these tasks can be particularly difficult without relying on 
visual feedback.

Barriers like these can make it difficult for users to complete multi-step tasks independently and 
to remain aware of what's happening while a task is being performed. This problem has become increasingly
important as many activities depend more on websites, applications, and other digital services.
Difficulties with nonvisual interactions can therefore limit many users' abilities to interact with
the modern digital world.

\subsection{Inputs and Outputs}
The intended input is the individual's voice as a form of control.
This can be expanded to spoken goals, preferences, clarification answers,
corrections, approvals, and stop requests. Users who are able may also supply 
keyboard or text input for assistance.

The intended outputs are actions on permitted services or the computer,
concise spoken progress and results, requests for clarification or
approval, and an accessible, reviewable task history. Completion feedback
must distinguish verified results, partial work, and unresolved failures.

\subsection{Stakeholders}
\begin{description}[style=nextline]
\item[Visually impaired individuals]
Primary stakeholders are visually impaired, English-speaking individuals who want to complete digital
tasks while retaining control through non-visual interactions.
\item[Users Wanting Non-Visual Interactions]
Secondary stakeholders are non-visually impaired individuals who still want the ability to complete
digital tasks without relying on visual feedback. They may be unable to view their computer screens
for other reasons, or may simply have a desire not to rely on their screen.
\end{description}

\subsection{Environment}
The expected environment is a Mac computer running macOS with Google Chrome,
a microphone, audio output, and internet access. Some tasks may also require access to the local Mac
environment. Users may also have existing accessibility tools like VoiceOver and keyboard navigation enabled.

\section{Goals}

\begin{enumerate}[label=G\arabic*.,leftmargin=*]
\item \textbf{Complete complex digital tasks independently.}
Users should be able to complete common, multi-step tasks across websites and applications without 
relying on visual feedback or sighted assistance. Success can be measured by task completion rate 
and the amount of sighted assistance that is required.

\item \textbf{Maintain awareness and control during digital tasks.}
Users should be able to understand relevant task progress and state changes, provide input when required,
and stop or redirect tasks when necessary. Success can be measured by the number of clarifying questions 
users feel the need to raise, the level of obedience in response to users' interventions and stoppages, and the
amount of caution presented by the program when it comes to critical tasks.

\item \textbf{Accurately receive results and execute commands.}
Users should be able to have confidence that the program is correctly tracking the system's state,
retrieving results, and executing their desired actions and commands. Success can be measured by a monitored session's 
percentage of accuracy with regards to command execution compared to the user's input, the current system state 
and its changes, and feedback or results being relayed to the user.

\item \textbf{Recover from errors and unexpected outcomes.}
Users should be able to identify unexpected, misunderstood, or failed actions and recover without restarting
the entire task or relying on sighted assistance. Success can be measured by the amount of feedback and clarifications
required for the user and program to understand the problem before continuing or correcting the task.

\item \textbf{Easy, understandable, and stable installation setup.}
Individuals responsible for setting up the interface should have a smooth setup process. They should also not be required to
assist or intervene after the initial setup is performed. Success can be measured by the number of clicks or commands needed,
the setup time before the program can be used, as well as how many times the setup helper is required to assist after installation.
\end{enumerate}

\section{Stretch Goals}
\begin{enumerate}[label=SG\arabic*.,leftmargin=*]
\item \textbf{Support additional applications and operating systems.}
If time permits, it would be beneficial to extend the implementation to multiple browsers and operating systems in order
to have the maximal amount of user access.

\item \textbf{Support a second voice channel.}
A useful extension is to allow users access the same task context through their computer as well as their cell phone. This extension
could allow for them to interact with their computer through voice-controlled interactions without being directly in front of it.

\end{enumerate}
